## 1. ข้อมูลภาพรวม (Overview)

- **ชื่อระบบ/ฟีเจอร์:** SabayJai Pantry — ระบบสต็อกของกินในบ้าน
- **เป้าหมายหลัก:** ช่วยให้คนในบ้านรู้ว่าตอนนี้ "มีของกินอะไร อยู่ตรงไหน และเหลือเท่าไร" เพื่อลดของเสีย ของซ้ำ และการซื้อซ้ำ
- **ผู้ใช้งาน (Users):** คนในบ้านที่ใช้ครัวร่วมกัน (จำนวนสมาชิกและสิทธิ์การใช้งาน — ดู Open Questions)

**บริบทโดยย่อ:**
บ้านมี **ตู้เย็น** และ **ที่เก็บหลายจุด** (เช่น ตู้กับข้าว ชั้นวาง ช่องแช่แข็ง ตะกร้า) ของที่จัดเก็บมีทั้ง **ของพร้อมกิน** และ **วัตถุดิบ** ผู้ใช้เป็นผู้เลือกเองว่าจะบันทึกข้อมูลอะไรบ้าง

---

## 2. ขอบเขต (Scope)

- **สิ่งที่ระบบทำได้ (In Scope):**
  - บันทึกของเข้าที่เก็บ พร้อมระบุตำแหน่งที่เก็บ (เช่น ตู้เย็น / ชั้นวาง)
  - ดูและค้นหารายการของทั้งหมดที่มีในบ้าน
  - ปรับจำนวนเมื่อหยิบใช้ / ทำอาหาร / ทิ้ง
  - แยกประเภทของพร้อมกิน กับ วัตถุดิบ
  - ดูข้อมูลตามตำแหน่งที่เก็บ

- **สิ่งที่ยังไม่ทำในตอนนี้ (Out of Scope):**
  - ระบบสั่งซื้อ/เชื่อมร้านค้าออนไลน์
  - ระบบบัญชีครัวเรือน/คำนวณโภชนาการเชิงลึก
  - การแชร์ข้อมูลออกนอกบ้านแบบสาธารณะ
  - (รอยืนยันเพิ่ม — ดู Open Questions)

## 3. รายการความต้องการ (User Stories & Requirements)

> ทั้งหมดเป็น **ข้อเสนอร่าง** ยังไม่ผ่านการยืนยันจากผู้ใช้ — เกณฑ์ตรวจรับบางข้อเป็นช่องว่างเพื่อรอการตัดสินใจ

### US-001 · บันทึกของเข้าที่เก็บ
- **ในฐานะ:** คนในบ้าน
- **ฉันต้องการ:** เพิ่มรายการของกินใหม่ พร้อมเลือกว่าอยู่ที่เก็บไหน และเป็นของพร้อมกินหรือวัตถุดิบ
- **เพื่อที่จะ:** รู้ว่ามีของนี้อยู่ในบ้าน
- **เกณฑ์การตรวจรับ (Acceptance Criteria):**
  - [ ] เพิ่มรายการได้สำเร็จภายในไม่กี่ขั้นตอน
  - [ ] ระบุตำแหน่งที่เก็บได้ (ตู้เย็น / จุดเก็บอื่น)
  - [ ] ระบุประเภทได้ (พร้อมกิน / วัตถุดิบ)
  - [ ] ข้อมูลที่ต้องกรอกอย่างน้อยเท่าไร → _รอตัดสินใจ (ดู OQ-03)_

### US-002 · ดูรายการของทั้งหมด
- **ในฐานะ:** คนในบ้าน
- **ฉันต้องการ:** เห็นภาพรวมของทุกอย่างที่มีในบ้านในที่เดียว
- **เพื่อที่จะ:** ตัดสินใจได้ว่าจะกินหรือซื้ออะไร
- **เกณฑ์การตรวจรับ (Acceptance Criteria):**
  - [ ] แสดงรายการของทั้งหมดที่มีอยู่
  - [ ] แยก/กรองตามตำแหน่งที่เก็บได้
  - [ ] ค้นหาด้วยชื่อของได้

### US-003 · ปรับจำนวนเมื่อหยิบใช้
- **ในฐานะ:** คนในบ้าน
- **ฉันต้องการ:** ลดหรือปรับจำนวนของเมื่อหยิบใช้หรือทิ้ง
- **เพื่อที่จะ:** ยอดคงเหลือตรงกับของจริง
- **เกณฑ์การตรวจรับ (Acceptance Criteria):**
  - [ ] ปรับจำนวนได้จากหน้ารายการ
  - [ ] เมื่อของหมด ให้แจ้งหรือย้ายออกจากรายการ → _รอตัดสินใจ (ดู OQ-05)_

### US-004 · ดูตามตำแหน่งที่เก็บ
- **ในฐานะ:** คนในบ้าน
- **ฉันต้องการ:** ดูว่าที่เก็บแต่ละจุด (เช่น ตู้เย็น) มีอะไรบ้าง
- **เพื่อที่จะ:** หยิบของได้เร็วและจัดของได้เป็นระเบียบ
- **เกณฑ์การตรวจรับ (Acceptance Criteria):**
  - [ ] เลือกดูทีละที่เก็บได้
  - [ ] จัดการรายชื่อที่เก็บ (เพิ่ม/แก้/ลบ) ได้ → _รอตัดสินใจ (ดู OQ-02)_

### US-005 · เตือนของใกล้หมดอายุ / ของหมด
- **ในฐานะ:** คนในบ้าน
- **ฉันต้องการ:** ได้รับการแจ้งเตือนเมื่อของใกล้หมดอายุหรือของที่ใช้บ่อยกำลังจะหมด
- **เพื่อที่จะ:** ใช้ของทันเวลาและไม่ต้องซื้อซ้ำโดยไม่จำเป็น
- **เกณฑ์ตรวจรับ (Acceptance Criteria):**
  - [ ] _ขึ้นกับ OQ-04: ระบบต้องมีการแจ้งเตือนหรือไม่ และช่องทางใด_

### US-006 · กันซื้อซ้ำ
- **ในฐานะ:** คนในบ้าน
- **ฉันต้องการ:** เช็กได้ว่า "ของชิ้นนี้มีอยู่แล้วหรือไม่" ก่อนซื้อ
- **เพื่อที่จะ:** ไม่ซื้อซ้ำและไม่สิ้นเปลือง
- **เกณฑ์การตรวจรับ (Acceptance Criteria):**
  - [ ] ค้นหาชื่อของได้เร็ว
  - [ ] เห็นจำนวนคงเหลือและตำแหน่งที่เก็บ

## 4. ข้อกำหนดอื่น ๆ (Non-functional Requirements)

> ยังต้องการการยืนยันจากผู้ใช้ — เสนอเป็นจุดตั้งต้น

- **การใช้งานบนมือถือ:** ควรใช้สะดวกบนมือถือ เพราะมักใช้ตอนอยู่ในครัวหรือตอนซื้อของ
- **ความเร็ว/ความง่าย:** บันทึกของต้องเร็วพอที่จะทำตอนของเข้าบ้านจริง ๆ
- **การใช้งานร่วมกันหลายคน:** สมาชิกในบ้านควรเห็นข้อมูลชุดเดียวกัน (รอยืนยัน — ดู OQ-06)
- **ความเป็นส่วนตัว:** ข้อมูลเป็นเรื่องภายในบ้าน ไม่ควรเปิดเผยต่อสาธารณะ
- **ภาษา:** ไทยเป็นหลัก
- **การทำงานแบบออฟไลน์:** _รอตัดสินใจ (ดู OQ-07)_

## 5. คำถามที่รอการตัดสินใจ (Open Questions)

| รหัส | คำถาม | ทำไมต้องตัดสิน |
|:---:|---|---|
| OQ-01 | มีสมาชิกในบ้านกี่คนที่ใช้ และใช้บัญชีร่วมหรือแยกกัน? | กระทบเรื่องสิทธิ์ การซิงก์ และการออกแบบข้อมูลผู้ใช้ |
| OQ-02 | ที่เก็บในบ้านมีจุดอะไรบ้าง (ตู้เย็น/ช่องแช่แข็ง/ตู้กับข้าว/ชั้นวาง/อื่น ๆ)? | กำหนดโครงสร้างตำแหน่งที่เก็บและหน้าจอกรอง |
| OQ-03 | ตอนบันทึกของ ต้องกรอกอะไรบ้างเป็นขั้นต่ำ (ชื่อ/จำนวน/หน่วย/วันหมดอายุ)? | กำหนดเกณฑ์ตรวจรับของ US-001 |
| OQ-04 | ต้องมีการแจ้งเตือนไหม (ใกล้หมดอายุ / ของหมด) และเตือนทางไหน? | เป็นตัวตัดสินว่าจะมี US-005 หรือไม่ |
| OQ-05 | เมื่อของหมด ควรหายไปจากรายการอัตโนมัติ หรือเก็บเป็นประวัติ? | กระทบพฤติกรรมระบบและข้อมูลย้อนหลัง |
| OQ-06 | ต้องใช้พร้อมกันหลายคนแบบเห็นข้อมูลเดียวกันแบบทันทีไหม? | กระทบความซับซ้อนของระบบและ NFR |
| OQ-07 | ต้องใช้งานได้ตอนไม่มีอินเทอร์เน็ตไหม? | กระทบสถาปัตยกรรมและเทคโนโลยีใน Phase ถัดไป |
| OQ-08 | การบันทึกของควรทำแบบไหน (พิมพ์เอง / สแกนบาร์โค้ด / ถ่ายรูป / เสียง)? | กระทบ UX และขอบเขตงาน |
| OQ-09 | เป้าหมายที่สำคัญที่สุดคืออะไร: ลดของเสีย / ลดซื้อซ้ำ / รู้ว่ามีอะไร / จัดบ้านเป็นระเบียบ? | ใช้จัดลำดับความสำคัญของ Story |
| OQ-10 | ใช้บนเว็บ มือถือ หรือทั้งคู่? | กระทบข้อจำกัดด้านแพลตฟอร์ม |

## 6. บันทึกเพิ่มเติม / ขั้นตอนถัดไป

- ให้ผู้ใช้ช่วยตอบ **Open Questions** ข้อที่มีผลมากที่สุดก่อน (แนะนำ OQ-01, OQ-03, OQ-09)
- เมื่อคำตอบครบพอ ให้ปรับปรุงเอกสารนี้และเปลี่ยนสถานะเป็น **Ready for Review**
- เอกสารนี้เป็น **หลักฐาน (Evidence)** เท่านั้น — การยอมรับเป็นสิทธิ์ของมนุษย์ (Human Acceptance)
