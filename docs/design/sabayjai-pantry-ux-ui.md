### 0.1 อัปเดตตามสคีมา v2 — สินค้า (Product) + ล็อต (Lot) + การเคลื่อนไหว (Movement)

> เพิ่มเมื่อ **2026-10-16** หลังเจ้าของโปรเจกต์เลือกโมเดล v2 · **หน้าตาและถ้อยคำที่ผู้ใช้เห็นไม่เปลี่ยน** (ยัง ≤3 ขั้นตอน · การ์ดยังใบละ 1 ชื่อสินค้า) — ที่เปลี่ยนคือ **"หนึ่งหน่วยบนจอ" ผูกกับอะไรในข้อมูล**

| จุดของแบบร่าง | เดิม (สคีมา v1) | ตอนนี้ (สคีมา v2) |
|---|---|---|
| การ์ดใน `#/items` | 1 แถว = 1 รายการที่มีจำนวนของตัวเอง | **1 การ์ด = 1 สินค้า** · ยอดที่แสดง = ผลรวมทุก**ล็อต**ที่ยังมีของ · ป้ายวันหมดอายุใช้ล็อตที่ใกล้ที่สุด |

| แถวใน `#/expiring` | แถว = รายการ | **แถว = ล็อต** (วันหมดอายุเป็นคุณสมบัติของล็อต) → สินค้าเดียวกันอาจโผล่หลายแถวถ้าต่างล็อต |
| แถวใน `#/used-up` | เก็บจำนวน+วันใช้หมดไว้ในตาราง | ล็อตยอด 0 · "จำนวนเดิม" อ่านจาก **movement ล่าสุด** (`out`/`discard`) · วันที่ใช้หมด = movement ล่าสุดของล็อตนั้น |
| ตัวเลข "N ชิ้น" ท้ายจุดเก็บ | นับรายการที่อ้างจุดเก็บนั้น | **นับล็อตที่ยังมีของ** (`countLotsInLocation`) |
| ตัวเลข "N ชิ้น" ท้ายหมวดหมู่ | นับรายการ | **นับสินค้า** (`countProductsInCategory`) |
| ฟอร์ม `#/add` | สร้างรายการใหม่ทุกครั้ง | หา/สร้าง **สินค้า** จาก (ชื่อ+หน่วย) แล้วสร้าง/รวม **ล็อต** จาก (สินค้า+จุดเก็บ+วันหมดอายุ) — autocomplete ชื่อดึงจาก `listProducts` |

## 1. หลักการออกแบบ

1. **งานหลัก 3 อย่างต้องจบไว** — "ดูว่ามีอะไร/ที่ไหน/เท่าไร" · "เพิ่มของ" · "ปรับจำนวนเมื่อหยิบใช้" จบได้จากจอเดียวต่อหนึ่งงาน โดยไม่ต้องเข้าหน้ารายละเอียด
2. **มือถือก่อน** — ออกแบบที่ 375 px ก่อน แล้วขยายขึ้น (768 = การ์ด 2 คอลัมน์ · 1280 = คอลัมน์กลางกว้างสุด ~960 px ไม่ยืดเต็มจอ) ไม่มี scroll แนวนอนทุกขนาด
3. **สีไม่เคยพูดคนเดียว** — ทุกสถานะมี "สี + ข้อความ" คู่กันเสมอ (ข้อ 4.2) เช่น แดง + "หมดอายุแล้ว · เลย 1 วัน"
4. **แตะง่าย ไม่พลาด** — เป้าหมายการแตะทุกปุ่ม ≥ 44×44 px (ข้อ 4.1)
5. **จอว่างต้องไม่เงียบ** — ทุกจอที่มีลิสต์มีสถานะว่างที่บอกว่าต้องทำอะไรต่อ
6. **ข้อมูลอยู่ที่เครื่อง** — ไม่มีคำว่า "ซิงก์/บัญชี/แชร์" ในถ้อยคำใด และทุกจอเปิดได้ทันทีจาก localStorage (ข้อ 4.3)

## 2. แผนผังการนำทาง และโครงหน้าจอมาตรฐาน

### 2.1 แผนผังการนำทาง (8 เส้นทางจากดีไซน์ข้อ 4.2)

```text
                     ┌──────────── Sheet เดียว (index.html) ────────────┐
                     │  หัวเรื่อง: สบายใจ Pantry        [＋ เพิ่มของ]     │
                     │  ───────────────────────────────────────────────  │
เปิดแอป → #/items ────┤  #/items │ #/add │ #/locations │ #/categories │   │
(ค่าเริ่มต้น)          │  #/expiring │ #/used-up │ #/shopping │ #/settings  │
                     │  ───────────────────────────────────────────────  │
                     │  พื้นที่เนื้อหา (เปลี่ยนตามเส้นทาง)                 │
                     │  ───────────────────────────────────────────────  │
                     │  แถบแจ้งเตือน/toast  (ลอยด้านล่าง)                 │
                     └──────────────────────────────────────────────────┘
```

- **ทางเข้า:** เปิดแอป → `#/items` เสมอ (เสร็จภารกิจหลัก #1 ทันที) · สรุปของใกล้หมดอายุอยู่ในแถบสรุปของจอนี้ (US-005)
- **ไม่มีจอซ้อน:** ทุกลิงก์เป็นการเปลี่ยน route ไม่มี modal เต็มจอ ยกเว้น dialog ยืนยันการลบ/รีเซ็ต

### 2.2 โครงหน้าจอมาตรฐาน (shell)

```text
┌─────────────────────────────────────────────┐
│ สบายใจ Pantry                    [＋ เพิ่มของ]│  ← หัวเรื่อง (ติดด้านบน)
├─────────────────────────────────────────────┤
│ [รายการ] [เพิ่ม] [จุดเก็บ] [หมวดหมู่] [ใกล้หมดอายุ] │  ← แถบเมนูเลื่อนแนวนอน
│ [ใช้หมดแล้ว] [ต้องซื้อ] [ตั้งค่า]             │     เส้นทางปัจจุบัน = ไฮไลต์
├─────────────────────────────────────────────┤
│                                             │
│  พื้นที่เนื้อหา (จอกว้าง: คอลัมน์กลาง ≤ 960 px) │
│                                             │
├─────────────────────────────────────────────┤
│ เดโมแบบร่าง · ข้อมูลอยู่ในเครื่องนี้เท่านั้น      │  ← เชิงอรรถ (จอ ≥768 px)
└─────────────────────────────────────────────┘
        ┌────────────────────────────────┐
        │ ย้าย "นมสด 1 ลิตร" เข้าใช้หมดแล้ว │  ← toast ลอยล่าง
        │                    [ย้อนกลับ ·5]│     (หายเองใน 5 วินาที)
        └────────────────────────────────┘
```

- **แถบเมนู:** รอบนี้ใช้ข้อความล้วน + เลื่อนแนวนอนภายในแถบได้ (ไม่ทำ bottom tab bar, ไม่ใช้ไอคอน) → ลดงานของ R001 และยกระดับเป็น bottom tab bar ได้ใน R008
- **โฟกัส:** ทุกองค์ประกอบที่กดได้มี focus ring 2 px สี `--sj-primary` (มองเห็นได้ทั้งคีย์บอร์ดและสลับแอป)

```text
│ │ 1 หัว · ตะกร้าผัก-ผลไม้ · วัตถุดิบ   [−] [1] [+] [ใช้หมดแล้ว] │ │
│ └───────────────────────────────────────────┘ │
│ ไข่ไก่ · 6 ฟอง · ตู้เย็น · วัตถุดิบ  [−][6][+] │ ← ไม่มีวันที่ = ไม่มีป้าย
└───────────────────────────────────────────────┘
```

- **หนึ่งการ์ด = หนึ่งสินค้า (สคีมา v2):** ยอดรวมมาจากทุก**ล็อต**ที่ยังมีของ · ป้ายวันหมดอายุใช้ล็อตที่ใกล้ที่สุด · กด − หักจากล็อตหมดอายุใกล้สุดก่อน (FEFO) · ของที่ไม่ระบุวันหมดอายุไม่มีป้าย
- **เรียงลำดับ:** แดงก่อน → เหลือง → ที่เหลือ (ชื่อ ก-ฮ) เพื่อให้เห็นของที่ต้องใช้ก่อน
- **แถบสรุป** เป็นทางเข้าหลักของ US-005 และต้องเห็นทันทีที่เปิดแอป
- **สถานะว่าง:** ไม่มีผลลัพธ์ → `ไม่พบของที่ตรงกับที่กรองไว้` + ปุ่ม "ล้างตัวกรอง" · ไม่มีของเลย → `ยังไม่มีของในตู้ — เริ่มจากเพิ่มชิ้นแรก` + ปุ่ม "＋ เพิ่มของ"
- **หมายเหตุ seed ของแบบร่าง:** ใส่หมายเหตุ `ของยาย` ให้ `ข้าวสาร` เพื่อสาธิตการค้นหาด้วยข้อความในหมายเหตุ (US-002) — เป็นข้อมูลสมมติของแบบร่างเท่านั้น
- **1 วินาที (ข้อ 4.3):** จอนี้คือจอที่เปิดมาเจอ ต้องไม่รอเครือข่ายและไม่มีการคำนวณหนัก

### 5.2 `#/add` · เพิ่มของ — **ลงลึก** (US-001)

```text
┌───────────────────────────────────────────────┐
│ เพิ่มของ                                      │
│ ชื่อของ *                    [นมส…▾ ของเดิม]   │ ← พิมพ์ 2–3 ตัวอักษรแล้วเสนอของเดิม
│ จำนวน *   [ 1 ]        หน่วย * [ กล่อง ▾ ]     │ ← มีตัวเลือก "พิมพ์หน่วยใหม่…"
│ จุดเก็บ * [ ตู้เย็น ▾ ]            [＋ เพิ่มจุดเก็บใหม่] │
│ หมวดหมู่  [ พร้อมกิน ▾ ]           [＋ เพิ่มหมวดใหม่]   │ ← inline-add ได้ทันที
│ วันหมดอายุ (ไม่บังคับ) [ 2026-10-18 ]          │
│ หมายเหตุ (ไม่บังคับ)  [ ของยาย                    ] │ ← ค้นหาครอบถึง
│                          [ยกเลิก]  [บันทึก]    │
└───────────────────────────────────────────────┘
```

- **ไม่เกิน 3 ขั้นตอน (US-001):** พิมพ์ชื่อ → เลือกจุดเก็บ → บันทึก (จำนวน/หน่วยมีค่าเริ่มต้นให้แก้)
- **ช่องบังคับ** = ชื่อ · จำนวน · หน่วย · จุดเก็บ · กด "บันทึก" แล้วไม่ครบ → ขึ้นข้อความใต้ช่องที่ขาด + โฟกัสไปช่องแรกที่ขาด (ไม่ใช่ alert)
- **พิมพ์หน่วยใหม่** → ตัวเลือกสุดท้ายของ dropdown เปิดช่องกรอก แล้วเพิ่มเข้าชุดหน่วยผ่าน `ensureUnit()` (seed ใช้ "ถ้วย" ที่ไม่อยู่ใน 11 หน่วยสำเร็จรูป)
- **สำเร็จแล้ว:** กลับไป `#/items` + toast `เพิ่ม "…" แล้ว` — และ **ล้างตัวกรองให้อัตโนมัติ** เพื่อให้เห็นการ์ดที่เพิ่งเพิ่มแน่นอน

### 5.3 `#/locations` · จุดเก็บ — **ลงลึก** (US-004)

```text
┌───────────────────────────────────────────────┐
│ จุดเก็บ (5)                          [＋ เพิ่ม] │
│ ┌───────────────────────────────────────────┐ │
│ │ ตู้เย็น            4 ล็อต     [แก้ชื่อ] [ลบ] │ │
│ │ ช่องแช่แข็ง        1 ล็อต     [แก้ชื่อ] [ลบ] │ │
│ │ ตู้กับข้าว          1 ล็อต     [แก้ชื่อ] [ลบ] │ │
│ │ ชั้นวางของ         2 ล็อต     [แก้ชื่อ] [ลบ] │ │
│ │ ตะกร้าผัก-ผลไม้     1 ล็อต     [แก้ชื่อ] [ลบ] │ │
│ └───────────────────────────────────────────┘ │
└───────────────────────────────────────────────┘
```

- **แก้ชื่อ:** เปลี่ยนแถวนั้นเป็นช่องกรอก + ปุ่ม "บันทึก"/"ยกเลิก" (ไม่ใช้ `prompt()`)
- **ลบจุดเก็บที่มีของ:** ขึ้นข้อความในแถว `ยังมีของค้างอยู่ 3 ล็อต — ย้ายของออกก่อนจึงจะลบได้` และปุ่มลบยังทำงานไม่ได้ (ตาม `ReferencedError` ในสัญญาข้อ 3.8) · นับด้วย `countLotsInLocation` (นับเฉพาะล็อตที่ยังมีของ) · ลบไม่ได้ = ไม่มี dialog
- **แตะแถว** → ไป `#/items` ที่กรองจุดเก็บนั้นไว้แล้ว (ทางลัดตาม US-004)
- **สถานะว่าง:** `ยังไม่มีจุดเก็บ — เพิ่มจุดแรกเพื่อเริ่มจัดของในบ้าน`

### 5.4 `#/categories` · หมวดหมู่ — **ลงลึก** (ข้อ 2.1 ข้อ 4)

- โครงเดียวกับ `#/locations` ต่างกันที่คำเรียก: "หมวดหมู่ (4)" · ตัวอย่าง `พร้อมกิน · 2 สินค้า`, `เครื่องปรุง · 1 สินค้า`
- เหตุผลที่ทำคู่กัน: กฎและสัญญาเหมือนกัน (`countProductsInCategory`, `ReferencedError` kind `category`) — แต่นับต่างกัน: **หมวดหมู่นับ "สินค้า"** เพราะหมวดหมู่อยู่ที่สินค้า ไม่ใช่ที่ล็อต
- **เริ่มต้น 4 หมวด:** พร้อมกิน · วัตถุดิบ · เครื่องปรุง · ของใช้ในครัว

### 5.5 `#/expiring` · ใกล้หมดอายุ — **โครงย่อ** (US-005)

```text
│ ต้องใช้ก่อน                                   │
│ ── หมดอายุแล้ว (1) ────────────────────────    │
│ ผักกาดขาว · 1 หัว · ตะกร้าผัก-ผลไม้ [เลย 1 วัน]  │
│ ── ใกล้หมดอายุ (2) ────────────────────────    │
│ นมสด 1 ลิตร · 1 กล่อง · ตู้เย็น    [เหลือ 2 วัน] │
│ โยเกิร์ต · 4 ถ้วย · ตู้เย็น        [เหลือ 3 วัน] │
```

- **แต่ละแถว = หนึ่งล็อต** (สคีมา v2) — สินค้าที่มีหลายล็อตต่างวันหมดอายุจะโผล่หลายแถว และมีข้อความบอกว่าเป็นล็อตไหน (วันหมดอายุ + จุดเก็บเป็นตัวแยก)
- ของที่ล็อตนั้นไม่ระบุวันหมดอายุ **ไม่ปรากฏในจอนี้** (US-005)
- ลงลึก (ปุ่มปรับจำนวน/ใช้หมดแล้ว/เรียงลำดับ) ตอนสร้างจริงใน R006

### 5.6 `#/used-up` · ใช้หมดแล้ว — **โครงย่อ** (US-007)

- **แถว = ล็อตที่ยอดเหลือ 0** (สคีมา v2 · ไม่มีตาราง `usedUp` แยก) · แสดง ชื่อสินค้า · จำนวนที่บันทึกไว้ตอนใช้หมด (**อ่านจาก movement ล่าสุด** `out`/`discard`) · `ใช้หมดเมื่อ 15 ต.ค. 2569` (movement ล่าสุดของล็อตนั้น) · ปุ่ม "นำกลับเข้ารายการ"
- กด "นำกลับ" → เปิดช่องกรอกจำนวนใหม่ แล้วเรียก `db.restoreLot(lotId, quantity)` ให้ล็อตกลับมามีของ (จึงกลับไปโผล่ `#/items` เอง) + toast
- **จำนวน "1 ก้อน" จึงเป็นค่าที่จำได้ ไม่ใช่ค่าที่ล็อตเก็บอยู่** — ถ้าอนาคตต้องการแก้ให้ล็อตจำยอดก่อนหมด ให้ตกลงเป็นคำตัดสินแยก
- ต้องไม่ปนกับรายการที่ยังมีอยู่ (แยกจอชัดเจน)

### 5.7 `#/shopping` · รายการที่ต้องซื้อ — **โครงย่อ** (US-008)

- ช่องพิมพ์ช่องเดียว + ปุ่ม "เพิ่ม" · แถวมี checkbox "ซื้อแล้ว" และปุ่ม "ลบ"
- ติ๊ก "ซื้อแล้ว" → รายการหายออกจากจอ + toast `ซื้อแล้ว — ลบออกจากรายการ`
- **ไม่ผูกกับรายการของ** (OQ-15): ไม่มีข้อความหรือปุ่มใดที่ชวนให้เข้าใจว่าของกลับเข้าสต็อกอัตโนมัติ

### 5.8 `#/settings` · ตั้งค่า — **โครงย่อ** (OQ-11 · ข้อ 4.4)

- "ข้อมูลในเครื่องนี้" — อธิบายสั้น ๆ ว่าข้อมูลอยู่ในเบราว์เซอร์เครื่องนี้ ไม่มีการส่งออก
- ปุ่มหลัก: **"รีเซ็ตข้อมูลตัวอย่าง"** → `confirm-dialog` → `resetToSeed()` → toast `คืนค่าข้อมูลตัวอย่างแล้ว` และกลับ `#/items`
- ยังไม่ใส่: การส่งออก/นำเข้าข้อมูล (ไม่ถูกขอใน requirement)

## 7. การเข้าถึงและความเข้าใจ (ตามข้อ 4.1 · 4.2)

- [x] ทุกสถานะมี **สี + ข้อความ** คู่กัน (ไม่สื่อด้วยสีอย่างเดียว)
- [x] ปุ่ม/ช่องกรอกที่มีผลกับงานหลัก สูง ≥ 44 px
- [x] ใช้ `aria-current="page"` ที่เมนูปัจจุบัน · toast เป็น `role="status"` `aria-live="polite"`
- [x] ทุกช่องกรอกมี `<label>` จริง (ไม่ใช้ placeholder แทนป้าย) · ข้อผิดพลาดผูกด้วย `aria-describedby`
- [x] โฟกัสเห็นชัด (outline 2 px) · ลำดับ Tab ตรงกับลำดับการอ่านบนจอ
- [x] 3 ขนาดจอ: 375 / 768 (การ์ด 2 คอลัมน์) / 1280 (คอลัมน์กลาง ≤960 px) และไม่มี scroll แนวนอน

**ผลตรวจจากการเปิดไฟล์จริง (2026-10-16):** ครบทั้ง 8 เส้นทางเรนเดอร์ได้ที่ 375 / 768 / 1280 px โดยไม่มีความกว้างเกินจอ (ไม่มี scroll แนวนอน) · แถบเมนูติดด้านบนแล้วไม่ทับเนื้อหาเมื่อเลื่อน · ปุ่ม/ชิป/เมนูสูง ≥ 44 px ทุกจุด (ช่องติ๊กใน "ต้องซื้อ" ตัวกล่องเล็กแต่พื้นที่กดคือทั้งแถว) · ไม่มีข้อความ error ในคอนโซลเบราว์เซอร์

**ผลตรวจรอบสคีมา v2 (2026-10-16 · เปิดในเบราว์เซอร์จริง):** หลังแปลง state ตัวอย่างเป็น `products` + `lots` + `movements` แล้ว ตรวจซ้ำทั้ง 8 เส้นทางที่ 375 / 768 / 1280 px → **ไม่มีความกว้างเกินจอทุกเส้นทาง** (วัด `documentElement.scrollWidth` เทียบ `innerWidth`) · ตรวจองค์ประกอบที่กดได้ **149 ตัวครบทั้ง 8 เส้นทางที่ 375 px** → สูง ≥ 44 px ทุกตัวที่มองเห็น (มี 2 ตัวที่วัดได้ 0 px เพราะอยู่ในฟอร์มย่อยที่ยังพับอยู่ — เปิดออกแล้วสูง 44 px) · ตรวจพฤติกรรมที่ผูกกับข้อมูล v2 แล้วได้ผลตามที่เขียนในหัวข้อ 0.1: "ใช้หมดแล้ว" ทำล็อตยอด 0 แล้วการ์ดหายจาก `#/items` และโผล่ `#/used-up` พร้อมจำนวน+วันที่จาก movement ล่าสุด · "นำกลับ" เติมยอดล็อตเดิมแล้วกลับไปโผล่ `#/items` · ฟอร์มเพิ่มของสร้างสินค้าใหม่ (และหน่วยใหม่)ได้ และเมื่อชื่อ+หน่วยซ้ำจะ**รวมเข้าล็อตเดิม** (ไม่เพิ่มการ์ดซ้ำ) · ข้อความห้ามลบเป็น "ยังมีของค้างอยู่ N ล็อต" · คอนโซลไม่มี error (มีแค่ log ของ Vite)

4. **ไม่ใช้ `prompt()`/`alert()`** — ใช้แถวแก้ชื่อและ dialog ของเราเอง เพื่อให้ควบคุมภาษาและหน้าตาได้ (แลกกับโค้ดเพิ่มเล็กน้อย)
