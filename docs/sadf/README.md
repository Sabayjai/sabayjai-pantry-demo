# SADF · SabayJai Approach & Development Framework (Public Edition)

> "มีหลัก พร้อมพลิกแพลง แบบบ้านสบายใจ"  
> กรอบวิธีทำงานร่วมกับ AI ที่เน้นความเข้าใจที่ตรงกันและการตรวจรับผลงานจริง

---

## 1. วงจร S · A · D · F

SADF ไม่ใช่ขั้นตอนบังคับแบบเส้นตรง แต่เป็น "จังหวะการมองงาน" ที่วนซ้ำได้ตามความเหมาะสม:

| รหัส | ชื่อ | คำถามนำ |
|:---:|------|---------|
| **S** | **Structure** (จัดงานให้ชัด) | เป้าหมาย ขอบเขต และข้อจำกัดของงานนี้คืออะไร? |
| **A** | **Align** (ทำความเข้าใจให้ตรงกัน) | ใครรับผิดชอบอะไร และจะตรวจผลงานอย่างไร? |
| **D** | **Delivery** (ลงมือให้เห็นผล) | ได้อะไรแล้ว ตรวจอะไรได้ และยังติดคำถามตรงไหน? |
| **F** | **Flow** (พางานต่อ) | ผลที่ได้ควรปรับอะไร ส่งต่ออะไร หรือเริ่มงานส่วนไหนต่อ? |

---

## 2. บทบาทสำคัญ

- **Human เป็นผู้ตัดสินใจ:** ถือเป้าหมาย ขอบเขต และการตรวจรับผลงาน (Acceptance)
- **AI เป็นผู้ช่วยและผู้ลงมือ:** เสนอทางเลือก ร่างเอกสาร และเขียนโค้ดตามกรอบที่ตกลงกัน

### Agent ที่มีในโปรเจกต์นี้ (`.claude/agents/`)

| Agent | Phase | ผลลัพธ์หลัก |
|---|---|---|
| `requirements-analyst` | 1 · เตรียม Requirement | `docs/requirements/*.md` (User Story + เกณฑ์ตรวจรับ + Open Questions) |
| `design-architect` | 2 · ออกแบบ | `docs/design/*.md` + แบบร่าง UX/UI + `docs/design/ux-ui/prototype.html` |
| `implementer` | 3 · ลงมือพัฒนา | โค้ดใน `src/**` + เทสต์ + หลักฐานตรวจรับใน `docs/work/R00x/02-result.md` |

ทุก Agent ใช้ **Asking Protocol** ร่วมกัน ([asking-protocol.md](asking-protocol.md)) — ถามในแชท กวาดให้ครบก่อน แล้วชุดละไม่เกิน 4 ข้อ · และ **ไม่มี Agent ใดตั้งสถานะงานเป็น Accepted เองได้** (การรับรองเป็นของเจ้าของโปรเจกต์)

---

## 3. หลักสำคัญที่ต้องยึดถือ

1. **มนุษย์เป็นผู้ตรวจรับผลงานเสมอ**
   - การอนุมัติหรือยอมรับผลงานเป็นสิทธิ์ของมนุษย์เท่านั้น AI มีหน้าที่จัดเตรียมผลลัพธ์ให้พร้อมตรวจ
2. **ถามเพื่อความชัดเจน ไม่เดาเอาเอง**
   - หากข้อมูลไม่เพียงพอหรือมีความขัดแย้ง ให้ระบุเป็นคำถามเปิด (Open Question) เพื่อให้มนุษย์ตัดสินใจ
3. **ส่งมอบเป็นชิ้นที่ตรวจรับได้**
   - งานแต่ละชิ้นควรมีขอบเขตที่พอดี จบได้ในรอบเดียว และสามารถตรวจดูผลลัพธ์ได้ง่าย
