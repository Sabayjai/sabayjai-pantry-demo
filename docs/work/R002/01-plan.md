## 1. เป้าหมายของ Release (Goal)

จบ Release นี้แล้วต้องได้จอจริง 2 จอที่ใช้งานได้ ไม่ใช่โครงอีกต่อไป:

1. **`#/locations`** — เห็นจุดเก็บ 5 จุดจาก seed + จำนวนล็อตที่ยังมีของ · เพิ่ม/แก้ชื่อ/พักใช้-เปิดใช้ได้ (แทนลบถาวรตามข้อเสนอ 2026-10-17 · OQ-R2-5/6 ปิดแล้ว)
2. **`#/categories`** — เห็นหมวดหมู่ 4 หมวดจาก seed + จำนวนสินค้า · เพิ่ม/แก้ชื่อ/พักใช้-เปิดใช้ได้ (แทนลบถาวร · OQ-R2-5/6 ปิดแล้ว)
3. ข้อความบนจอ**ตรงกับสิ่งที่ทำได้จริง** — ตามข้อเสนอเจ้าของโปรเจกต์ 2026-10-17: master data **ไม่มีปุ่มลบถาวร มีแค่ active/inactive** จึงไม่มีทางตันแบบ OQ-R16 อีกต่อไป (ไม่ต้องเขียนข้อความ "ย้ายของออกก่อน" ที่ทำไม่ได้จริง)

## 2. ขอบเขต (Scope)

- **ทำ (In Scope):** Sprint S1 · S2 ข้างล่างทั้งหมด — UI แบบ **Card ล้วน** (ภาษาเดียวกับ `#/items`) + ต่อคำสั่งชั้นข้อมูลที่มีอยู่แล้ว + องค์ประกอบที่ใช้ (`location-card`/`category-card` บนโครง `.card` เดิม · `status-badge` สถานะใช้งาน/พักใช้ · `filter-chips` ทั้งหมด/ใช้งาน/พักใช้ · `confirm-dialog`) + ตรวจ 3 ขนาดจอ
- **ไม่ทำ (Out of Scope):**
  - ลบถาวร (hard delete) ทั้งจุดเก็บและหมวดหมู่ — ตามข้อเสนอ 2026-10-17 ใช้ active/inactive แทน · คำสั่ง `deleteLocation`/`deleteCategory` ใน db ยังอยู่ (ใช้ในเทสต์) แต่จอ R002 ไม่เรียก
  - ย้ายของระหว่างจุดเก็บ (`moveLot` · US-009 → R005) — รอบนี้ไม่บล็อกแล้วเพราะไม่มีปุ่มลบถาวรให้ตัน
  - กรอง `#/items` ตามจุดเก็บ/หมวดหมู่ (US-002 → R004) — การ์ดกดไม่ได้ทั้งใบ (OQ-R2-2 = C ปิดแล้ว) ทางลัดกรองจริงยกไป R004
  - ฟอร์มเพิ่มของ (R003) · ปรับจำนวน/undo (R005) · PWA/Responsive เต็มรูป (R008) · Deploy (R009)
- **ของที่มีอยู่แล้ว (ไม่ต้องทำใหม่):** คำสั่งชั้นข้อมูลครบ + มีเทสต์คลุมแล้ว (`addLocation`/`renameLocation`/`deleteLocation`/`countLotsInLocation` · ฝั่ง category ครบคู่ · `validateName` กันชื่อว่าง/ยาวเกิน 60/ชื่อซ้ำ · `ReferencedError`) — เทสต์ Vitest 77 ตัวผ่านใน R001 · รอบนี้คือ "เอาของที่มีมาต่อจอ" ไม่ใช่เขียนชั้นข้อมูลใหม่

## 3. Sprint & Task

### Sprint S1 · จุดเก็บ (US-004)

> เป้าหมาย: `#/locations` ใช้งานได้ครบ — เพิ่ม/แก้ชื่อ/พักใช้-เปิดใช้ (แทนลบถาวร · OQ-R2-5/6 ปิดแล้ว) + ตัวเลขนับเฉพาะ "ล็อตที่ยังมีของ" (ล็อตยอด 0 ไม่นับ)

- [ ] **Task 0 · ธง `isActive` ชั้นข้อมูล** ✅ พร้อมลงมือ (OQ-R2-5 = A) — เติม `isActive: true` ให้จุดเก็บ/หมวดหมู่ใน `seed.js` + `normalizeState` เติม true ให้ข้อมูลเก่า + คำสั่ง `setLocationActive`/`setCategoryActive` + เทสต์ · กฎ: พักได้แม้มีของค้าง (ของเดิม/ประวัติอยู่ครบ แค่ซ่อนจาก dropdown รับของใหม่ใน R003)
- [ ] **Task 1 · องค์ประกอบ Card + `confirm-dialog`** — สร้างใน `src/ui/components.js` บนโครง `.card`/`.cards` เดียวกับ `#/items` (ภาษาเดียวกัน · ไม่ใช้แถว): การ์ดมีชื่อ · จำนวน (ล็อตที่ยังมีของ / สินค้า) · `status-badge` (ใช้งาน/พักใช้) · ปุ่มแก้ชื่อ · ปุ่มพักใช้/เปิดใช้ · dialog ยืนยันก่อนพักใช้ทุกครั้ง (ปุ่มทำลายสีแดง · `Esc` = ยกเลิก · OQ-R2-3 ปิดแล้ว) — ทำครั้งเดียวแล้ว S2 เอาไปใช้ต่อ
- [ ] **Task 2 · ลิสต์จุดเก็บแบบ Card + ตัวกรอง** — แทนโครงใน `src/views/locations.js` ด้วยการ์ดจริงจาก `listLocations()` + จำนวนจาก `countLotsInLocation()` + `filter-chips` (ทั้งหมด/ใช้งาน/พักใช้ · OQ-R2-6) · หัวจอ "จุดเก็บ (N)" + ปุ่ม "＋ เพิ่ม" · สถานะว่าง: `ยังไม่มีจุดเก็บ — เพิ่มจุดแรกเพื่อเริ่มจัดของในบ้าน`
- [ ] **Task 3 · เพิ่มจุดเก็บ** — ฟอร์มเพิ่มเรียก `addLocation()` · ชื่อว่าง/ยาวเกิน 60/ชื่อซ้ำ → ข้อความใต้ช่อง (ไม่ใช้ `alert`/`prompt`) — ถ้อยคำตาม copy deck
- [ ] **Task 4 · แก้ชื่อ** — ปุ่ม "แก้ชื่อ" เปลี่ยนแถวนั้นเป็นช่องกรอก + "บันทึก"/"ยกเลิก" (ไม่ใช้ `prompt()`) เรียก `renameLocation()` · กฎซ้ำเหมือน Task 3
- [ ] **Task 5 · พักใช้/เปิดใช้จุดเก็บ** — ไม่มีปุ่มลบในจอ · การ์ดที่พักใช้มีป้าย "พักใช้" + ปุ่ม "เปิดใช้" · กดพักใช้ → `confirm-dialog` → `setLocationActive(id, false)` → toast · พักได้แม้มีของ (OQ-R2-5 = A: ของเดิมอยู่ครบ ซ่อนจาก dropdown ของใหม่เท่านั้น)
- [ ] **Task 6 · แถวกดไม่ได้** — ✅ OQ-R2-2 ปิดแล้ว (C) แถวเป็นข้อความอ่านอย่างเดียว มีแค่ปุ่มแก้ชื่อ/พักใช้กดได้ · ทางลัดไป `#/items` แบบกรองจริงยกไป R004
- [ ] **Task 7 · ตรวจรับ S1** — `npm test` ผ่าน · `npm run build` ผ่าน · เปิด 375/768/1280 px ไม่มี scroll แนวนอน · ปุ่ม/ช่องกรอกสูง ≥ 44 px · ข้อความไทยทั้งหมด

### Sprint S2 · หมวดหมู่ (ข้อ 2.1 ข้อ 4)

## 5. ข้อสังเกต / คำถามที่ต้องตัดสินใจ (Open Questions)

> สถานะ: **รอตอบในแชท** (ตาม asking-protocol — ถามเป็นข้อความธรรมดา ชุดละไม่เกิน 4 ข้อ) · ค่าเริ่มต้นข้างล่างคือสิ่งที่ AI จะใช้ถ้าเจ้าของโปรเจกต์บอกว่า "ตามที่แนะนำ"

- **OQ-R2-1 · ข้อความปุ่มลบที่เป็นทางตัน:** ⏳ **ถูกแทนด้วยข้อเสนอ inactive (ดู OQ-R2-5/6)** — ถ้าตกลงใช้ inactive จะไม่มีปุ่มลบถาวรในจอ จึงไม่ต้องเขียนข้อความทางตันอีก
- **OQ-R2-2 · "แตะแถว" คืออะไร:** ✅ **ปิด 2026-10-17 — ตอบ C** แถวกดไม่ได้ (มีปุ่ม Action ท้ายแถวแล้วทั้งแถวกดไม่ได้ กันกดพลาด) มีแค่ปุ่มกดได้ · ทางลัดกรองจริงไป R004
- **OQ-R2-3 · dialog ยืนยัน:** ✅ **ปิด 2026-10-17 — ตอบ A** สร้าง `confirm-dialog` จริง (ปุ่มทำลายสีแดง · `Esc` = ยกเลิก) — ใช้ตอนยืนยันพักใช้/เปิดใช้ต่อ
- **OQ-R2-4 · ฟอร์มเพิ่ม:** ✅ **ปิด 2026-10-17 — ตอบ A** ฟอร์ม inline ใต้หัวจอ ลองก่อน ถ้ายาวค่อยปรับ
- **OQ-R2-5 · พักทั้งที่มีของได้ไหม:** ✅ **ปิด 2026-10-17 — ตอบ A** พักได้แม้มีของค้าง ของเดิม/ประวัติอยู่ครบ แค่ไม่ให้เลือกเติมของใหม่เข้าไป (ซ่อนจาก dropdown รับของใหม่ R003)
- **OQ-R2-6 · การ์ด + สถานะ + ตัวกรอง:** ✅ **ปิด 2026-10-17 — ตอบ A** การ์ดมีป้ายสถานะ (ใช้งาน/พักใช้) + `filter-chips` (ทั้งหมด/ใช้งาน/พักใช้) — เป็น normal UX pattern ตรงกับตัวกรอง `#/items` ใน R004 ใช้ชุดเดียวกันได้

**หนี้ที่รับรู้แล้ว (ไม่ถาม):** ลบจุดเก็บที่มีของไม่ได้จนกว่า R005 จะมี US-009 (`moveLot` ย้ายทั้งล็อต) — รอบนี้แก้ด้วยถ้อยคำ ไม่ใช่ฟีเจอร์ · แตะแถวแล้วยังกรองไม่ได้จนกว่า R004 จะมีตัวกรอง — รอบนี้เป็นทางลัดไป `#/items` เฉย ๆ
