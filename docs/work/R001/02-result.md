### ⓪.3 ลงมือตามคำตอบชุดที่ 3 (2026-10-16) — D5 · D7 · D10 · D11 (+ D8 · D9 ที่ค้างอยู่)

> เจ้าของโปรเจกต์ตอบในแชท: **D5 ก. · D7 ก. · D10 ข. · D11 ก.** (ข้อความเต็มอยู่ที่ `data-model-review.md` §5 "บันทึกคำตอบ ชุดที่ 3") → **คำถามฝั่งข้อมูลปิดครบทั้ง 11 ข้อ** และ S2 ยัง **Ready for Review** เหมือนเดิม (ไม่เปลี่ยนสถานะ)

- **D10 = ข. · เก็บยอดเดิมไว้ที่ล็อต (เจ้าของโปรเจกต์สั่งเพิ่มวิธีคำนวณใหม่เอง):**
  - เพิ่ม `lots[].usedUpQuantity` = **ยอดตอนก่อนหักครั้งสุดท้าย** (ยอดที่ทำให้ล็อตนั้นเป็น 0) · ล็อตที่ยังมีของเก็บ `0` · กลับมามีของ → ล้างเป็น `0`
  - `seed.js` ใส่ค่าตั้งต้น (เนยจืด `1` · มะนาว `3` · ล็อตที่ยังมีของ `0`) · `selectors.usedUpQuantityFromMovements(movements)` = ฟังก์ชันบริสุทธิ์ที่ไล่ประวัติตาม `at` แล้วหาว่ายอดก่อนหมดเท่าไร
  - `db.js`: `syncUsedUpQuantity()` ถูกเรียกจากทุกคำสั่งที่แตะยอด (`receiveStock` · `consumeProduct` · `setLotQuantity` · `restoreLot`) — การคุมค่าเป็นหน้าที่ของโค้ดตามที่เจ้าของโปรเจกต์ระบุ
  - **คำสั่งที่ขอเพิ่ม:** `db.recalculateUsedUpQuantities()` (เก่งทั้งชุดหรือเฉพาะล็อต) + ปุ่ม **"คำนวณจำนวนเดิมใหม่จากประวัติ"** ที่ `#/settings` — ทางออกเมื่อค่าที่เก็บไม่ตรงกับประวัติ
  - `normalizeState()` **เติมฟิลด์ที่ขาดจากประวัติ** ⇒ ข้อมูลสคีมา v2 ที่มีอยู่เดิมได้ค่าเดิมที่ถูกต้องทันที โดยไม่ต้องรีเซ็ตและไม่ต้อง migration ใหม่ (ตรวจบนเบราว์เซอร์แล้ว: เนยจืด 1 · มะนาว 3)
- **D8 = สำเนาก่อนรีเซ็ต:** คีย์ **`sabayjai-pantry.backup`** เก็บข้อความดิบ + วันที่ + เหตุผล ก่อนทับทุกครั้งที่ `resetToSeed()` (รวมกรณีอ่านข้อมูลไม่ได้/ข้อมูลเวอร์ชันใหม่กว่า) · `readBackupInfo()` · `restoreBackup()` · ปุ่ม **"กู้คืนข้อมูลเดิม"** ที่ `#/settings` · สำเนาเพี้ยน/เก่าเกินไป ⇒ ไม่แตะข้อมูลปัจจุบัน แล้วบอกเหตุผล
- **D9 = ตรวจรูปร่างข้อมูลรายฟิลด์:** `normalizeState()` ตรวจทุกคอลเลกชัน (ตัด `id` ซ้ำ · ล็อต/ประวัติกำกับสินค้า-ล็อตที่ไม่มีอยู่ · ยอดที่ไม่ใช่ตัวเลข · วันที่ที่ไม่มีจริง เช่น `2026-02-30` · `type` ที่ไม่รู้จัก → `adjust` · รหัสที่หาย → ออกใหม่) แล้ว `console.warn` สรุปสิ่งที่ซ่อม · **เก็บรายการที่ถูกต้องไว้ ไม่ทิ้งทั้งก้อน**
- **D5 · D7 · D11 = ไม่ต้องแก้โค้ด** — บันทึกเป็นคำตัดสิน + เหตุผลในดีไซน์ข้อ 0 และ `data-model-review.md` §5
- **จอ `#/settings` เพิ่ม 2 หัวข้อ + 3 ปุ่ม:** เดิมมีแค่รีเซ็ต → ตอนนี้มี "ข้อมูลตัวอย่าง" · "ข้อมูลสำรอง" (สำเนาล่าสุด/เวลา/เหตุผล/ขนาด + ปุ่มกู้คืน) · "จำนวนเดิม" ของของที่ใช้หมดแล้ว (คำอธิบาย + ปุ่มคำนวณใหม่)
