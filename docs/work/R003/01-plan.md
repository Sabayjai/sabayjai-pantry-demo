## 1. เป้าหมายของ Release (Goal)

จบ Release นี้แล้วต้องบันทึกของใหม่ได้จริงในไม่เกิน 3 ขั้นตอน (พิมพ์ชื่อ → เลือกจุดเก็บ → บันทึก) โดยจำนวน/หน่วยมีค่าเริ่มต้นให้แก้:

1. **ฟอร์ม `#/add`** ครบทุกช่อง: บังคับ ชื่อ · จำนวน · หน่วย · จุดเก็บ / ไม่บังคับ หมวดหมู่ · วันหมดอายุ · หมายเหตุ
2. **ช่วยกรอกของเดิม:** พิมพ์ชื่อ 2–3 ตัวอักษรแล้วเสนอของที่เคยบันทึกให้เลือก (เลือกแล้วเติมหน่วย/หมวดหมู่/หมายเหตุให้)
3. **หน่วยพิมพ์ใหม่ได้ + เพิ่มจุดเก็บ/หมวดหมู่ในหน้านี้ได้ทันที** (dropdown แสดงเฉพาะที่ใช้งาน — ของที่พักใช้ใน R002 ไม่โผล่)
4. บันทึกสำเร็จ → กลับ `#/items` + toast `เพิ่ม "…" แล้ว` (ล้างตัวกรองอัตโนมัติเป็นของ R004 — รอบนี้ `#/items` ยังไม่มีตัวกรอง จึงแค่กลับไปจอรวม)

## 2. ขอบเขต (Scope)

- **ทำ (In Scope):** S1 ทั้งหมด — ฟอร์ม + autocomplete + inline-add จุดเก็บ/หมวดหมู่ + ข้อความใต้ช่อง + toast สำเร็จ
- **ไม่ทำ (Out of Scope):** ปรับจำนวน/undo (R005) · ค้นหา/กรอง `#/items` (R004) · toast undo 5 วิ (R005 — รอบนี้ toast ธรรมดาอ่านอย่างเดียว)
- **ของที่มีอยู่แล้ว:** `receiveStock` (รวมล็อตเดิมเมื่อสินค้า+จุดเก็บ+วันหมดอายุตรงกัน · แยกล็อตเมื่อวันหมดอายุต่าง) · `ensureUnit` · `validateReceiveInput` + เทสต์คลุมแล้ว — รอบนี้คือ "เอามาต่อจอ" ไม่เขียนชั้นข้อมูลใหม่

## 3. Sprint & Task

### Sprint S1 · ฟอร์มเพิ่มของ (US-001)

- [ ] **Task 1 · โครงฟอร์ม + ช่องบังคับ** — เขียน `src/views/item-form.js` ใหม่: ชื่อ (text) · จำนวน (number ค่าเริ่ม 1) · หน่วย (select 11 ตัว + `พิมพ์หน่วยใหม่…` → ช่องกรอก → `ensureUnit`) · จุดเก็บ (select เฉพาะ `listLocations({activeOnly:true})`) · บันทึกไม่ครบ → ข้อความใต้ช่องที่ขาด + โฟกัสช่องแรก (ไม่ใช้ alert)
- [ ] **Task 2 · ช่องไม่บังคับ + inline-add** — หมวดหมู่ (select เฉพาะที่ใช้งาน + `＋ เพิ่มหมวดใหม่` inline) · จุดเก็บมี `＋ เพิ่มจุดเก็บใหม่` inline เช่นกัน · วันหมดอายุ (`input type=date` ไม่บังคับ) · หมายเหตุ (text ไม่บังคับ ยาวเกิน 200 มีข้อความบอก)
- [ ] **Task 3 · ช่วยกรอกของเดิม** — พิมพ์ชื่อ ≥ 2 ตัวอักษร → รายการเสนอจาก `listProducts()` (ชื่อขึ้นต้น/มีข้อความนั้น เรียง ก-ฮ จำกัด 5) → เลือกแล้วเติมหน่วย/หมวดหมู่/หมายเหตุของสินค้านั้นให้ (จำนวน/จุดเก็บ/วันหมดอายุไม่เติม — เป็นของล็อตใหม่)
- [ ] **Task 4 · บันทึก + toast** — เรียก `receiveStock()` → สำเร็จ: ไป `#/items` + toast `เพิ่ม "…" แล้ว` (สร้าง `toast()` ธรรมดาใน `components.js` — `role=status` หายเอง 5 วิ ไม่ใช่ undo) · ล้มเหลว (เช่นจุดเก็บโดนพักใช้ระหว่างกรอก): แสดงข้อความใต้ช่องนั้น
- [ ] **Task 5 · ตรวจรับ S1 + ปิด Release** — `npm test` ผ่าน · `npm run build` ผ่าน · 375/768/1280 ไม่มี scroll แนวนอน · ปุ่ม/ช่องกรอก ≥ 44 px · เขียน `docs/work/R003/02-result.md` พร้อมหลักฐาน

## 4. เกณฑ์การตรวจรับของ Release (Acceptance Criteria)

 mapping US-001 ทั้ง 6 ข้อ (เจ้าของโปรเจกต์เป็นผู้ติ๊ก):

- [ ] เพิ่มของ 1 ชิ้นได้ในไม่เกิน 3 ขั้นตอน (พิมพ์ชื่อ → เลือกจุดเก็บ → บันทึก)
- [ ] ไม่กรอกชื่อ/จำนวน/หน่วย/จุดเก็บครบแล้วบันทึกไม่ได้ + มีข้อความบอกใต้ช่องที่ขาด
- [ ] วันหมดอายุ · หมวดหมู่ · หมายเหตุ ไม่กรอกก็บันทึกได้
- [ ] หน่วยเลือกจาก 11 ตัวสำเร็จรูปได้ และพิมพ์หน่วยใหม่เองได้ (เช่น `กระสอบ` แล้วครั้งหน้าโผล่ในรายการ)
- [ ] พิมพ์ชื่อ 2–3 ตัวอักษรแล้วมีของเดิมให้เลือกใช้ซ้ำ
- [ ] เพิ่มหมวดหมู่ใหม่ในหน้านี้ได้ทันที แล้วเลือกใช้ได้โดยไม่ต้องออกจากหน้า (+ จุดเก็บเช่นกันตามแบบร่าง 5.2)
