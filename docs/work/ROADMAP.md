## โครงลำดับชั้นของงาน (Hierarchy)

งานทั้งหมดจัดเป็น 3 ระดับ:

```
Release (Rxxx)   ← หมุดหมายใหญ่ที่ส่งมอบได้ ตรวจรับระดับ Release
└── Sprint        ← งานย่อยที่จบได้ในแต่ละขั้น ภายใน Release นั้น
    └── Task       ← งานยิบย่อยที่ต้องทำใน Sprint
```

- **Release** = 1 โฟลเดอร์ `docs/work/R00x/` มี `01-plan.md` (แผน: Sprint + Task) และ `02-result.md` (ผล + หลักฐานตรวจรับ)
- **Sprint** = หัวข้อใน `01-plan.md` ของ Release นั้น
- **Task** = checkbox ใต้ Sprint
- **กติกา:** แต่ละ Sprint ต้อง **จบในตัวและตรวจรับได้** · เจ้าของโปรเจกต์ (มนุษย์) เป็นผู้ตรวจรับทุกรอบ

## Definition of Done (ระดับโปรเจกต์)

จะถือว่าโปรเจกต์เสร็จเมื่อ **ทุกเกณฑ์ตรวจรับใน requirement ติ๊กครบ** และมีหลักฐานครบ:

- [ ] US-001 … US-008 ติ๊กครบทุกเกณฑ์
- [ ] NFR ข้อ 4.1–4.5 ผ่าน (Responsive 3 ขนาด · ภาษา · 1 วินาที · localStorage/ออฟไลน์ · PWA)
- [ ] เดโมเปิดแล้วมี seed พร้อมใช้ มีสถานะเหลืองและแดงครบ
- [ ] ปุ่มรีเซ็ตข้อมูลตัวอย่างทำงานได้
- [ ] ขึ้นโฮสต์แล้วเข้าใช้งานด้วย URL จริงได้ (HTTPS สำหรับ PWA)
- [ ] เขียน `02-result.md` ของทุก Release พร้อมหลักฐาน

## จุดที่ต้องตัดสินใจใน Release แรก (R001)

- **สแต็กของเดโม:** แนะนำ *Static HTML/CSS/JS + Vanilla JS (ไม่ต้องมีขั้นตอน build)* — เบา ตรวจงานได้ทันที เปิดแล้วเร็ว เหมาะกับเดโม Frontend Only + PWA · ทางเลือกสำรองคือ Vite + เฟรมเวิร์ก ถ้าตั้งใจต่อยอดระยะยาว
- **ปลายทาง Deploy:** แนะนำ **Vercel** (เชื่อม Git แล้ว deploy อัตโนมัติ · HTTPS ให้เอง ซึ่งจำเป็นต่อการติดตั้ง PWA) · ทางเลือกอื่น เช่น GitHub Pages — ยืนยันซ้ำใน R009
