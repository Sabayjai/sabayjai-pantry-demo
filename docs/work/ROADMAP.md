## โครงลำดับชั้นของงาน (Hierarchy)

งานทั้งหมดจัดเป็น 3 ระดับ:

```
Release (Rxxx)   ← หมุดหมายใหญ่ที่ส่งมอบได้ ตรวจรับระดับ Release
└── Sprint        ← งานย่อยที่จบได้ในแต่ละขั้น ภายใน Release นั้น
    └── Task       ← งานยิบย่อยที่ต้องทำใน Sprint
```

- **Release** = 1 โฟลเดอร์ `docs/work/R00x/` มี `01-plan.md` (แผน: Sprint + Task) และ `02-result.md` (ผล + หลักฐานตรวจรับ)
- **Sprint** = หัวข้อใน `01-plan.md` ของ Release นั้น
- **Task** = checkbox ใต้ Sprint
- **กติกา:** แต่ละ Sprint ต้อง **จบในตัวและตรวจรับได้** · เจ้าของโปรเจกต์ (มนุษย์) เป็นผู้ตรวจรับทุกรอบ

## บันทึกการตัดสินใจของ Release แรก (R001) — ✅ ปิดแล้ว 2026-10-16

> เดิมหัวข้อนี้เป็น "ข้อเสนอแนะรอตัดสิน" · เจ้าของโปรเจกต์ปิดคำตัดสินเมื่อ 2026-10-15 และเพิ่มคำตัดสินงานออกแบบจอเมื่อ 2026-10-16 · รายละเอียดเชิงเหตุผลอยู่ใน `docs/design/sabayjai-pantry.md` และ `docs/work/R001/01-plan.md`

- **สแต็กของเดโม:** ✅ **Vite + Vanilla JS (ไม่ใช้เฟรมเวิร์ก)** — เลือกความสะดวกในการต่อยอด (HMR, จัดการ ES module, ต่อ PWA plugin ใน R008) แลกกับมีขั้นตอน build (`npm run build` → `dist`) · ข้อเสนอเดิม "Static HTML/CSS/JS ไม่มี build" ไม่ถูกเลือก
- **ปลายทาง Deploy:** ✅ **Cloudflare Pages** (ล็อก Node ด้วย `.nvmrc` ให้ HTTPS เอง ซึ่งจำเป็นต่อการติดตั้ง PWA) · ข้อเสนอเดิม Vercel ไม่ถูกเลือก · ยืนยันซ้ำใน R009
- **การนำทาง:** ✅ **หน้าเดียว + hash routing** — ไม่ต้องตั้ง `_redirects` และไม่ชนพฤติกรรม SPA fallback ของ Pages
- **งานออกแบบจอ:** ✅ **S3 · UX/UI Draft** อยู่ใน R001 หลัง S2 (ชั้นข้อมูลไม่ต้องรอแบบจอ) และR002 เป็นต้นไปต้องมีแบบร่างก่อนสร้างจอจริง
- **เมนูหลัก (OQ-R11 · OQ-R14 · OQ-R15):** ✅ **3 รูปแบบตามขนาดจอ** — ≥1024 px เมนูซ้าย · 768–1023 px แถวบน · <768 px **☰ + dropdown** · และเมนูเหลือ **7 รายการ** (ตัด "เพิ่ม" ออก เพราะมีปุ่ม `＋ เพิ่มของ` ที่หัวจอ) · `#/add` ยังเป็นเส้นทางจริง
- **ย้ายของระหว่างจุดเก็บ (OQ-R16):** ✅ **เพิ่มเป็น US-009 ทำใน R005** — เพราะ US-004 สั่งให้ "ย้ายของออกก่อนจึงจะลบจุดเก็บได้" แต่ระบบยังไม่มีทางย้าย ⇒ ร่างถ้อยคำที่ `docs/requirements/sabayjai-pantry.md`
- **โครงข้อมูลสต็อก + คำถามฝั่งข้อมูล:** ✅ **สคีมา v2 = สินค้า (Product) + ล็อต (Lot) + การเคลื่อนไหว (Movement)** และคำถามฝั่งข้อมูล **D1–D11 ปิดครบเมื่อ 2026-10-16** — รวม D8 สำเนาข้อมูลก่อนรีเซ็ต + กู้คืน · D9 ตรวจรูปร่างข้อมูลรายฟิลด์ · D10 เก็บยอดก่อนหมดไว้ที่ล็อต (`usedUpQuantity`) พร้อมคำสั่งคำนวณใหม่จากประวัติ · รายละเอียดที่ `docs/work/R001/data-model-review.md`
